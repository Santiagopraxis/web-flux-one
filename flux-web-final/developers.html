Bienvenido a la documentación de desarrollo de **fluX**. Ofrecemos una API unificada y robusta que permite a las plataformas automatizar flujos de dinero inmediatos conectándose directamente con las redes de pagos en tiempo real locales.

Dispersión (Payouts)
Envía fondos a cuentas bancarias en tiempo real con confirmación en segundos.
Recaudo (Pay-ins)
Recibe pagos inmediatos por transferencias, llaves alias o códigos QR.
Cuentas y Validación
Verifica la identidad del titular de la cuenta antes de enviar fondos para mitigar fraudes.
Webhooks Push
Recibe notificaciones inmediatas en tu servidor tan pronto como ocurra un evento.

Autenticación

Cada petición a las APIs de **fluX** requiere el header de autorización con tu Bearer token obtenido de forma segura. El token de sesión tiene una vigencia limitada y debe renovarse periódicamente.

Errores

La API utiliza códigos de estado HTTP estándar para indicar el éxito o fracaso de las peticiones. Cada error retorna una estructura con códigos legibles.

400
Bad Request
Petición malformada o parámetros con sintaxis inválida.
401
Unauthorized
Token de acceso ausente, vencido o con firma inválida.
404
Not Found
El recurso solicitado (cuenta, transacción, etc.) no existe.
409
Conflict
Conflicto transaccional. Por ejemplo, uso repetido de una llave de idempotencia.
422
Unprocessable Entity
Petición bien formateada pero con errores de negocio (fondos insuficientes, banco rechazó).
500
Internal Server Error
Error del servidor de fluX. Implementar reintento con backoff exponencial.

Dispersión (Payouts)

Envía dispersiones a cualquier cuenta bancaria en México a través de la red **SPEI** de forma inmediata. Las transacciones se procesan al instante en horario operativo de SPEI, liquidando en segundos. fluX abstrae la complejidad de la conexión directa y conciliación con BANXICO.

Postman Collection: Download Collection — Payouts v1

Casos de Uso

  • Dispersión de Nómina: Automatiza el pago de salarios a miles de empleados masivamente.
  • Pagos a Proveedores: Paga facturas de insumos al instante sin procesos bancarios manuales.
  • Liquidación de Escrow: Entrega fondos recaudados a conductores, repartidores o comercios.
  • Reembolsos Inmediatos: Retorna saldos por devoluciones directamente a la tarjeta de débito del cliente.

Flujo de la Transacción

1
Petición POSTPOST
Tu plataforma envía la petición con la CLABE destino, monto y una referencia única a /v1/transactions/payouts.
2
Procesamiento y SPEISPEI
fluX valida la petición, debita tu cuenta concentradora y enruta los fondos por SPEI. Retorna estado INITIALIZED. Los fondos se liquidan en segundos.

Ciclo de Vida del Payout

Una transferencia SPEI pasa por las siguientes etapas: INITIALIZED (registrada) → PENDING (en cola de envío) → PROCESSING (enviada a SPEI) → LIQUIDATED (acreditada con éxito en el banco destino) ó FAILED (rechazada por el banco receptor).

Penny Validation

La API de **Penny Validation** permite verificar la pertenencia de una cuenta bancaria mandando un monto mínimo de centavos ($0.01 MXN) al destinatario. Este proceso genera de forma asíncrona un **CEP (Comprobante Electrónico de Pago)** oficial validado por Banco de México (BANXICO), el cual nos devuelve el RFC, CURP y nombre legal real del dueño de la cuenta bancaria.

Consideración Importante: El tiempo de procesamiento para recuperar el CEP depende de la velocidad del banco beneficiario al procesar el centavo y de la plataforma del CEP de BANXICO (promedio de 90 segundos).

Crear Validación de Centavo

POST /v1/partners/transactions/penny_validation 
curl -X POST https://flux.praxisglobe.com/api/v1/partners/transactions/penny_validation \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: unique-pv-key-12345" \
  -d '{
    "client_id": "09b1c156-73c7-62e1-9a3e-bf705f8f3cbe",
    "source_instrument_id": "709448c3-7cbf-454d-a87e-feb23801269a",
    "destination_clabe": "734180000069183455",
    "description": "Validacion de cuenta",
    "external_reference": "1234567"
  }'

Webhooks

Los webhooks te permiten reaccionar a eventos en tiempo real. fluX envía un request POST a tu servidor tan pronto como ocurre un movimiento (depósito SPEI entrante).

Registrar Webhook

curl -i -X POST https://flux.praxisglobe.com/api/v1/partners/webhooks/register \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "834f8a44-245f-460d-83ed-f731c38e967a",
    "url": "https://midominio.com/webhooks/receptor",
    "event": "PAYIN",

  }'

Validación con X-Secret-key

Cada webhook incluye el header X-Secret-key con el valor de tu secreto. Valídalo en tu middleware de Express u otro servidor antes de procesar el JSON para mitigar peticiones spoofing.

Recaudo (Pay-ins)

Para recibir recaudos en Colombia por medio de **Bre-B**, fluX ofrece dos flujos simplificados: **Llaves Referenciadas** y generación de **Códigos QR** estandarizados bajo EMVCo.

1. Llaves Referenciadas

Las Llaves Referenciadas son alias registrados ante el Banco de la República vinculados a tu cuenta de fluX. Los pagadores solo digitan tu alias en su banca móvil para transferirte dinero, gatillando automáticamente un webhook en tu servidor al completarse.

Prefijo Obligatorio
Todas las llaves alfanuméricas deben iniciar estrictamente con @FLX.
Formato del Alias
Solo se permiten caracteres alfanuméricos después del prefijo (ej: @FLXPAYMENTS2025).

Crear una Llave Aliases

POST /v1/accounts/{account_id}/keys 
curl -i -X POST https://flux.praxisglobe.com/api/v1/accounts/acc_12345/keys \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "alias": "Mi primera llave fluX",
    "key_config": "open_input",
    "open_input": "@FLXMyBusiness123"
  }'

Genera de forma programática códigos QR (estáticos o dinámicos de un solo uso) listos para desplegar en tu flujo de checkout online o físico.

Webhooks

fluX Colombia empuja eventos inmediatos a tu webhook cuando una transferencia de Bre-B se completa o falla, permitiéndote liberar órdenes, acreditar saldos o disparar alertas al instante.

Middleware / Receptor en Node.js

Este es un ejemplo de webhook handler en Express con validación robusta del token secreto (enviado en el header X-Secret-key) y control de estados: 

const express = require('express');
const app = express();
app.use(express.json());

const WEBHOOK_SECRET = process.env.FLUX_WEBHOOK_SECRET;

app.post('/webhooks/receptor', (req, res) => {
  // 1. Validar header X-Secret-key
  const secretKey = req.headers['x-secret-key'];
  if (secretKey !== WEBHOOK_SECRET) {
    console.error('Invalid secret key');
    return res.status(401).json({ error: 'Unauthorized' });
  }

  // 2. Procesar el payload del evento
  const { event, id, status, external_reference } = req.body;

  switch (event) {
    case 'payment.completed':
      console.log(`✅ Payment ${id} completed - ref: ${external_reference}`);
      // Acredita la orden en tu base de datos
      break;

    case 'payment.failed':
      const { failure_reason } = req.body;
      console.log(`❌ Payment ${id} failed: ${failure_reason}`);
      // Registra la falla o notifica a soporte
      break;

    default:
      console.log(`Unknown event: ${event}`);
  }

  // 3. Confirmar la recepción devolviendo 200 OK
  res.status(200).json({ received: true });
});

app.listen(3000, () => {
  console.log('CO Webhook handler listening on port 3000');
});

Política de Reintentos

Si tu servidor no responde con un estado HTTP exitoso (2xx), fluX reintentará de forma automática según el siguiente cronograma:

IntentoDemoraDescripción
1roInmediatoIntento de entrega inicial.
2do5 segundosPrimer reintento automático tras falla.
3ro5 segundosÚltimo reintento. Si falla, el evento se marca como FAILED.

Buenas Prácticas de Integración

Responder con 200
Asegura responder de forma inmediata con estado 200 OK. Evita ejecutar procesos pesados de forma síncrona en el request.
Deduplicación
Valida el ID único del pago recibido para evitar cobros u operaciones duplicadas en caso de reintentos de red.

Seguridad

🛡️ Directrices de Seguridad obligatorias
  • Gestión de Secretos: Nunca guardes contraseñas ni tokens JWT en tu código fuente. Utiliza variables de entorno o almacenes seguros como AWS Parameter Store o HashiCorp Vault.
  • Validación de Webhooks: Verifica siempre el header X-Secret-key antes de procesar cualquier payload entrante en tus rutas públicas.
  • Idempotencia: Envía siempre el header Idempotency-Key (UUID v4 o v5) en operaciones de dispersión (Payouts) para evitar cobros dobles por problemas de timeout.
  • Canal Seguro (HTTPS): Todas las comunicaciones con fluX deben realizarse exclusivamente sobre canales cifrados con TLS 1.3. Los endpoints HTTP no seguros serán rechazados.
